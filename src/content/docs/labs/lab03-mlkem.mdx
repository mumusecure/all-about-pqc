## 과제

**과제 1. 코드 읽기.** 파일의 함수 이름 옆 주석에 FIPS 203 알고리즘 번호가 있습니다. `kpke_keygen`, `kpke_encrypt`, `kpke_decrypt`, `decaps_internal` 을 16장 4절·7절의 수식과 한 줄씩 대응시키세요. 특히 다음을 찾으세요.

- 행렬 성분을 `rho + bytes([j, i])` 로 뽑는 곳과, 암호화에서 전치를 읽는 곳
- PRF 카운터 $N$ 이 $0, \dots, 2k$ 로 쓰이는 순서
- 재암호화 비교 `c == c2` (실제 구현은 왜 이렇게 쓰면 안 되는가?)

**과제 2. 적합성 검사 (선택).** 회귀값은 "코드가 바뀌었는지"만 알려 줍니다. FIPS 203 과 **바이트 단위로** 같은지는 NIST 의 ACVP 테스트 벡터(GitHub 의 `usnistgov/ACVP-Server` 저장소에 ML-KEM keyGen·encapDecap JSON 파일이 있습니다)로 확인합니다. `keygen_internal(d, z)` 와 `encaps_internal(ek, m)` 이 벡터의 `ek`, `dk`, `c`, `k` 를 재현하는지 검사하는 스크립트를 쓰세요. 하나라도 틀리면 어디가 다른지(바이트 순서? 행렬 인덱스? 카운터?) 추적하는 과정이 가장 큰 공부입니다.

**과제 3. 정확성의 경계.** `PARAMS` 에 사용자 파라미터를 추가하거나 `failure_probability` 를 직접 불러, 다음 표를 채우세요.

| 바꾼 것 (ML-KEM-768 기준) | 암호문 크기 | $\log_2 \delta$ |
|---|---|---|
| 기본 | 1088 | |
| $d_u = 9$ | | |
| $d_v = 3$ | | |
| $\eta_1 = 3$ | | |
| $k = 4$, 나머지 그대로 | | |

어느 손잡이가 "바이트당" 가장 비싼지 결론을 내리세요(16장 연습 6).

**과제 4. 이론과 관측.** `--noise 768 --trials 200` 으로 잡음을 모아 표준편차를 구하고, 16장 표의 76.5 와 비교하세요. $\eta_1$ 을 크게(예: 8) 바꿔 실제 복호 실패가 나오는 지점을 찾고, `failure_probability` 의 예측과 맞는지 보세요.

**과제 5. 상수 시간 압축 (KyberSlash).** `compress(x, 1)` 을 나눗셈 없이 계산하는 함수를 쓰세요.

```python
def compress1_ct(x):
    return ((((x << 1) + 1665) * 80635) >> 28) & 1

assert all(compress1_ct(x) == compress(x, 1) for x in range(Q))
```

80635 가 어디서 왔는지 설명하고(16장 연습 10), 같은 방법으로 `compress(x, 4)` 와 `compress(x, 10)` 의 나눗셈 없는 버전을 만드세요. 상수와 시프트 양을 어떻게 골라야 모든 입력에서 맞는지가 핵심입니다.
